GitSwitch v2.0.0 turns the account switcher into a full git client. Everything v1 did still works the same, and every action still runs as the account the repo uses. New: a changes panel and commit box, merge with a conflict editor, stashes, blame, compare, reflog and bisect, remotes, rebase and reword, signing, worktrees and submodules, a command palette, repo tabs and themes.

## Install or update

macOS, Linux, WSL, Git Bash:
```sh
curl -fsSL https://raw.githubusercontent.com/macdipu/gitswitch/main/install.sh | sh
```
Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/macdipu/gitswitch/main/install.ps1 | iex
```
Run the same line again to update. Your accounts, rules and repo choices are kept.

## New

- **Changes and commits, in the desktop app.** The *Uncommitted changes* row at the top of History opens a panel beside the log.
  - Stage, unstage and discard whole files, single hunks, or single lines (click the gutter, Shift+click for a range). A discard always keeps what it removed in `git stash`, and says how to get it back.
  - A commit box with a summary and a description, your recent messages, a sign-off box, co-author suggestions from the repo's history, and **Amend the last commit** (only while it isn't pushed). A message from a commit that failed comes back.
  - Right-click a file to ignore it (the file, its extension or its folder, for everyone or just for you), see its blame, or its history.
- **A better diff view.** Every diff has a toolbar: unified or side by side, word-level changes, ignore whitespace, syntax colours, and collapse per hunk. Long diffs draw the first 400 lines with a *Show more* button.
- **Merge and conflicts.** *Merge into…* in a branch's menu shows what would come in and which files are likely to clash, then fast-forwards, merges or squashes. If files clash, the merge stops: a banner lists them, a dialog shows yours, theirs and an editable result, and **Continue** or **Abort** finish it. The same banner handles a rebase or cherry-pick you started in a terminal.
- **Stashes.** *Stashes…* lists every stash with its kind (parked by GitSwitch, kept from a discard, or yours), files and diffs. Apply, pop, start a branch from one, drop (Undo brings it back), or stash your changes with a message. Parked changes and smart switch work as before.
- **Look into history.** *Blame* shows who last changed each line, with the account behind each commit, and steps back one commit at a time. *File history* follows renames. *Compare two refs…* shows what a branch changed since the two split, or the direct difference. *Reflog…* finds commits no branch reaches any more and brings one back as a branch. *Find the commit that broke it* is a guided bisect. *Code contains* in Filters (or `code:text`) finds commits that added or removed a text.
- **Remotes.** *Remotes…* adds, renames, re-points and removes remotes and says which account each URL uses. Delete a branch on the server from its menu, *Fetch and forget deleted branches*, and **force push with lease**: it lists the commits on the server it would overwrite and yours, runs the account check, and refuses if someone pushed since you looked. It is never a plain force push. Check out any commit or tag and come back with *Back to <branch>*.
- **Rebase and rewrite (CLI).** `gitswitch rebase <onto>` and `gitswitch rebase -i` (reorder, squash, fixup, reword, drop), `gitswitch reword <commit>` and `gitswitch fixup-into <commit>`. Only commits that are not pushed, never merge commits, always a plan first, a clash stops instead of aborting, and one Undo puts everything back. `gitswitch redo` does an undone change again.
- **Commit signing.** Give an account an SSH or GPG signing key (`gitswitch account edit work --signing-format ssh`, or the account form). Repos that use the account sign their commits, git can verify them, and the log shows a check, or a warning for a bad signature. GitSwitch prints the public key to add to your host as a signing key.
- **Worktrees and submodules (CLI).** `gitswitch worktree` and `gitswitch submodule` list and manage them. A worktree always uses the same account as its main repo, and each submodule fetches as the account that owns its own URL.
- **Start a repo.** *New repo…* on the Repos page, or `gitswitch init`, runs `git init` and gives the repo its account.
- **Everything faster to reach.** A command palette (Ctrl/⌘+K) for every page and action, repo tabs, live refresh (the changes list and history follow your editor), and a Theme setting: System, Light, Dark or Dim.
- **Terminal app.** The History page gains a Changes view (`s`), amend in the commit form, branches (`B`), tags (`t`, `T`), stashes (`h`) and ignore (`i`).

## Fixed

- A repo with no commits yet (right after `git init`) failed `branch`, `changes` and `fetch`. It now works from the first commit.
- Folder rules matched a linked worktree's own folder, so a worktree outside the rule's folder could pick another account than its main repo.
- The Repos table no longer overflows the window at narrow widths.

## Good to know

- Anything that rewrites history refuses commits a remote branch already has. Force push is the one exception, and it always shows what it would overwrite first.
- The desktop screens for rebase, worktrees and submodules are still to come; use the CLI for those.
- The new desktop screens were checked on Linux. If you see something off in the macOS or Windows window, please open an issue.
