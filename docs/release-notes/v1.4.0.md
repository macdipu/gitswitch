GitSwitch v1.4.0 helps with everyday branch work. You can see your uncommitted files at a glance, take them to another branch or park them on their own, start a branch, commit and push it as the right account, see what you would push or pull, tidy up merged branches, and undo the last change GitSwitch made.

## Install or update

macOS, Linux, WSL, Git Bash:
```sh
curl -fsSL https://raw.githubusercontent.com/macdipu/gitswitch/main/install.sh | sh
```
Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/macdipu/gitswitch/main/install.ps1 | iex
```
Run the same line again to update. Your accounts, rules and repo choices are kept.

## New

- **Smart switch or park.** When you switch branch with uncommitted changes, GitSwitch asks whether to take them along or park them. Use `gitswitch switch <branch> --smart` or `--park` to skip the question.
  - When git refuses because your changes would be overwritten, GitSwitch sets them aside, switches and puts them back, staged files staged.
  - If some files clash with the new branch, you fix the conflict markers there, in your editor or IDE, while your original changes stay safe. Then choose **I've fixed them** (`gitswitch resolve --done`), **Go back** to the old branch with your changes exactly as before (`gitswitch resolve --abort`), or **Park instead** (`gitswitch resolve --park`). The desktop app shows these above the commits, and the terminal app uses `R`.
- **Push and open a pull request.** The desktop app's Push button, `p` in the terminal app, or `gitswitch push [--open]` push the current branch with the repo's account and say which account pushed.
  - The first push puts the branch on the remote and tracks it. GitSwitch never forces a push: when the remote has commits you don't have, it explains what to do instead.
  - After a push, open a pull request (a merge request on GitLab) on GitHub, GitLab or Bitbucket in one click, or with `--open`.
- **Commit.** Commit the staged files, or every change with `--all`, as the repo's account: the desktop app's "Commit…" button, `C` in the terminal app, or `gitswitch commit -m <message> [--all]`.
  - It refuses when nothing is staged (without `--all`), when files are in conflict, in the middle of a merge or rebase, or when the repo's email is not its account's.
  - Undo takes the commit back and keeps the changes in your files. Picking files and lines stays with your IDE.
- **Compare with the remote.** See the commits you would push and the ones you would pull: the "Compare" button by the sync status in the desktop app (with Push or Update when only one applies), `S` in the terminal app, or `gitswitch branch compare [--json]`.
- **Account check before pushing.** When not-pushed commits on the branch were made as another of your accounts, GitSwitch says so before pushing and offers to fix them first, push them as they are, or cancel. Without a terminal, `gitswitch push` needs `-y` to push them as they are.
  - When the repo's email is not its account's, so new commits would show someone else, the desktop app offers to use the account's name and email, the terminal app uses `i`, and `gitswitch use <account> --once` fixes it in a terminal.
- **New branch.** Start a branch at the current commit, or at any commit, branch or tag, and switch to it with your uncommitted changes: "New branch…" in the desktop branch menu or "New branch here" on a commit, `n` and `N` in the terminal app, or `gitswitch branch new <name> [--from <commit>]`.
  - An optional name prefix, such as `feature/`, goes in front of new branch names: `gitswitch set branch-prefix feature/`, or Settings in either app.
  - If your changes clash with the commit you start from, nothing changes. It works from a detached HEAD too, to keep commits made there.
- **Committed on the wrong branch?** Move the commits you haven't pushed to a new branch, and put the old one back where its remote is: "Move not-pushed commits to a new branch…" in the desktop branch menu, `M` in the terminal app, or `gitswitch branch new <name> --move`. Your uncommitted changes stay as they are, and Undo puts the commits back.
- **Delete merged branches.** Remove the local branches already merged into the remote's default branch: "Delete merged branches…" in the desktop branch menu, `D` in the terminal app, or `gitswitch branch prune [-y] [--dry-run]`.
  - The current branch, main, master, the default branch and branches checked out in another worktree are never deleted. A branch whose remote is gone but that isn't merged (for example after a squash merge) is kept and named.
  - Undo brings them back, with their remote tracking.
- **Remember what to do with uncommitted changes.** `gitswitch set switch-changes ask|smart|park` for every repo, or with `--repo` for one. Also on the Settings page of both apps, and when GitSwitch asks: **Remember my choice for this repo** in the desktop app, `S` or `P` in the terminal app, `s!` or `p!` in a terminal.
  - Without a terminal, a flag or a saved choice, `gitswitch switch` with uncommitted changes now stops and says how to choose, instead of switching the way git does.
- **Park.** Leave uncommitted changes on their branch, new files included, and switch clean. When you come back, GitSwitch offers them back: **Restore**, look first, or not now.
  - Parked changes are ordinary stashes (`gitswitch park: <branch>`), visible in `git stash list`, IntelliJ and VS Code. They are never deleted automatically.
  - Restoring puts staged files back staged. If they clash with the branch, nothing changes and they stay parked.
  - `gitswitch parked` lists them; `gitswitch parked restore|show|drop [<n>]` works on one. The desktop app lists them above the commits and badges branches that have some, and the terminal app uses `P`.
- **Undo.** Undo the last switch, park, new branch, move, branch cleanup, commit, revert, drop, rollback, cherry-pick or fix-author in a repo. Use the **Undo** button in the message after the change or in the History toolbar. You can also press `Shift+U` in either app, or run `gitswitch undo`.
  - Undo puts the branch back exactly as it was. After a rollback, files you edited since are kept.
  - It refuses, and changes nothing, when undoing would lose work: new commits or a pull since, commits already pushed, or uncommitted changes in files it would change.
  - `git gc` doesn't delete a dropped commit while it can still be undone.
- **Uncommitted files at a glance.** The History toolbar, the terminal app, `gitswitch branch`, `log` and `status` show how many files are staged, changed, new or in conflict, and how many sets of changes are parked on the branch. `gitswitch status --json` includes them too.
