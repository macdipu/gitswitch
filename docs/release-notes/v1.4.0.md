GitSwitch v1.4.0 (in progress) helps with everyday branch work. You can see your uncommitted files at a glance, take them to another branch or park them on their own, and undo the last change GitSwitch made.

## Install or update

macOS, Linux, WSL, Git Bash:
```sh
curl -fsSL https://raw.githubusercontent.com/macdipu/gitswitch/main/install.sh | sh
```
Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/macdipu/gitswitch/main/install.ps1 | iex
```
Run the same line again to update. Your accounts, rules and repo choices are kept.

## New

- **Smart switch or park.** When you switch branch with uncommitted changes, GitSwitch asks whether to take them along or park them. Use `gitswitch switch <branch> --smart` or `--park` to skip the question.
  - When git refuses because your changes would be overwritten, GitSwitch sets them aside, switches and puts them back, staged files staged.
  - If some files clash with the new branch, you fix the conflict markers there, in your editor or IDE, while your original changes stay safe. Then choose **I've fixed them** (`gitswitch resolve --done`), **Go back** to the old branch with your changes exactly as before (`gitswitch resolve --abort`), or **Park instead** (`gitswitch resolve --park`). The desktop app shows these above the commits, and the terminal app uses `R`.
- **Remember what to do with uncommitted changes.** `gitswitch set switch-changes ask|smart|park` for every repo, or with `--repo` for one. Also on the Settings page of both apps, and when GitSwitch asks: **Remember my choice for this repo** in the desktop app, `S` or `P` in the terminal app, `s!` or `p!` in a terminal.
  - Without a terminal, a flag or a saved choice, `gitswitch switch` with uncommitted changes now stops and says how to choose, instead of switching the way git does.
- **Park.** Leave uncommitted changes on their branch, new files included, and switch clean. When you come back, GitSwitch offers them back: **Restore**, look first, or not now.
  - Parked changes are ordinary stashes (`gitswitch park: <branch>`), visible in `git stash list`, IntelliJ and VS Code. They are never deleted automatically.
  - Restoring puts staged files back staged. If they clash with the branch, nothing changes and they stay parked.
  - `gitswitch parked` lists them; `gitswitch parked restore|show|drop [<n>]` works on one. The desktop app lists them above the commits and badges branches that have some, and the terminal app uses `P`.
- **Undo.** Undo the last switch, revert, drop, rollback, cherry-pick or fix-author in a repo. Use the **Undo** button in the message after the change or in the History toolbar. You can also press `Shift+U` in either app, or run `gitswitch undo`.
  - Undo puts the branch back exactly as it was. After a rollback, files you edited since are kept.
  - It refuses, and changes nothing, when undoing would lose work: new commits or a pull since, commits already pushed, or uncommitted changes in files it would change.
  - `git gc` doesn't delete a dropped commit while it can still be undone.
- **Uncommitted files at a glance.** The History toolbar, the terminal app, `gitswitch branch`, `log` and `status` show how many files are staged, changed, new or in conflict, and how many sets of changes are parked on the branch. `gitswitch status --json` includes them too.
