GitSwitch v1.3.0 makes the default account optional and lets a repo ask every time. It splits the desktop app into its own program and explains git errors in plain words. It also adds a guided setup in the desktop app, commit details and "load more" in History, and many safety fixes.

## Install or update

macOS, Linux, WSL, Git Bash:
```sh
curl -fsSL https://raw.githubusercontent.com/macdipu/gitswitch/main/install.sh | sh
```
Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/macdipu/gitswitch/main/install.ps1 | iex
```
Run the same line again to update. Your accounts, rules and repo choices are kept.

## Changes to how an account is chosen

- **The default account is optional.** Adding your first account no longer makes it the default. If you already have a default, it stays.
  - Set or remove it with `gitswitch default <id>` or `gitswitch default --none`. The desktop app has a "When a repo has no account yet" chooser and "Remove as default" on the Accounts page. In the terminal app, press `d` (on the default it removes it).
- **With no default**, a repo with no saved account and no matching rule asks which account to use. If nobody can answer (a script, CI, a background fetch), git doesn't connect, rather than guess.
- **An answer is saved for the repo only when you say so.** Tick "always use it for this repo" in the popup, or type `2!` in the terminal. Otherwise the answer is used for that one connection.
- **A repo can ask every time.** Use `gitswitch use --ask` or "Ask every time" on the Repos page. Such a repo skips rules and never saves an answer. `gitswitch forget` (or "Follow rules and default") puts it back.
- A default on one host is no longer used on another host.

## Two programs, one install

- `gitswitch` is the program git runs on every clone, pull and push. It's now a small static program with no desktop code: about 5 MB, and a few milliseconds per run on Linux.
- `gitswitch-app` is the desktop app. The installers download both and check both against `SHA256SUMS`, then `gitswitch install` installs both. The app goes to `~/Applications/GitSwitch.app` on macOS. On Windows and Linux it sits next to `gitswitch`, with a Start-menu or app-menu entry.
- `gitswitch ui` opens the app. On Linux without WebKitGTK 4.1, only the terminal programs are installed, and `gitswitch ui` says why. Set `GITSWITCH_CLI_ONLY=1` to skip the app.
- If you download the files by hand, put both in one folder and run `gitswitch install`.

## New

- **Guided setup in the desktop app.** It connects git, adds an account, shows how to put the key on GitHub/GitLab/Bitbucket, tests the login and sets your projects folder. Run it again from Settings. `gitswitch setup` explains each step too.
- **Plain-language errors** for the problems people hit most: key not added on the host, unknown host key, no access to the repo, push with the wrong account, network blocked, rejected push, key file permissions and more. They appear in the CLI, the terminal app and the desktop app, with what to do next.
- **Commit details.** Click a commit in the desktop app, press Enter in the terminal app, or run `gitswitch show <commit>` to see the full message and the changed files.
- **Load more history.** Use "Load 400 more" in the desktop app, `m` in the terminal app, or `gitswitch log -n <count>`.
- `gitswitch rule remove owner:<org>` removes a rule by its value. Rule numbers still work.
- The desktop app fits small windows, groups account actions under a "More" menu, saves settings as you change them and folds passing health checks. It also reads better with a screen reader.

## Fixes

- **History safety.** `fix-author`, `drop` and `rollback` refuse when they would touch commits already pushed (including through a merge), or when this clone lacks a copy of the remote branch. They also say when git kept your uncommitted changes in the stash.
- **The ssh hook never hangs and never guesses.** A background `git fetch` no longer freezes, parallel fetches ask once, and a git config that can't be read stops the connection instead of using any key. A default nobody chose is no longer written into the repo's `user.email`.
- **New keys are made without showing the passphrase in the process list.** Key files are written atomically with the right permissions.
- **Known-host checks** follow your ssh config, so GitHub over port 443 counts as known.
- **Installing** replaces the program atomically. It says "added to PATH" only when it actually wrote a profile (fish too). Uninstall puts back your old global email only if it's still unset.
- **Commit text** from git is cleaned of terminal control characters before it's shown.
- **Edge cases** in account rename, date filters, branch switching, repo scanning, Windows drive paths as clone URLs and very long git output.
- **Terminal app:** selections stay in range, the terminal is restored on exit or a signal, pop-ups scroll and filter, and Esc no longer quits.
- **Symlinked folders:** repos in a folder reached through a symlink (such as `/var` on macOS) can be pinned and removed.
- **Linux installer:** it detected WebKitGTK wrongly, and the menu entry broke on paths with spaces.

## Notes

- Release workflow actions are pinned to commit SHAs, and Linux builds run on Ubuntu 22.04 so they start on older systems.
- This release still publishes `gitswitch-linux-<cpu>-cli` for older install scripts. That copy will be removed in a later release.
- The programs are not code-signed yet. macOS and Windows may warn the first time you run a downloaded file. The install scripts handle this on macOS.
